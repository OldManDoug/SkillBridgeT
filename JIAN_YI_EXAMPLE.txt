THE FOUR PARTS
Frontend/Pages/       What appears on screen: Razor files ending .cshtml.
Backend/Pages/        What a page does: matching C# files ending .cshtml.cs.
Backend/JianYi/       Account rules, database queries and sign-in helpers.
database/            The SQL file that creates tables and starting data.

Both halves of a page have the same name. Example:
Frontend/Pages/JianYi/Admin/Users/Edit.cshtml
Backend/Pages/JianYi/Admin/Users/Edit.cshtml.cs

The folder name identifies the owner. Program.cs removes that name from
the public URL: JianYi/Admin/Users becomes /Admin/Users.

ONE COMPLETE EXAMPLE: CREATE A USER

1. OPEN THE PAGE
   Frontend/Pages/JianYi/Admin/Users/Edit.cshtml

   @page "{id:long?}" makes this file a page. The optional id is for editing.
   @model identifies its C# PageModel class: EditModel.
   ViewData["Title"] supplies the browser/page title.
   @Model.IsCreate chooses the Create or Edit wording.
   <form method="post"> submits the fields to this page's POST handler.
   asp-for="Input.Email" links a control to Input.Email in the C# file.
   required/type/minlength/maxlength check input in the browser.
   asp-validation-for shows the error for one field.
   asp-validation-summary shows the form's errors together.
   asp-page generates a link to another Razor page.
   asp-route-id adds a record's ID to that link.
   @if shows a block only when its condition is true.
   @* ... *@ is a Razor comment; it is not sent to the browser.

   Razor also adds an anti-forgery token to this POST form. This helps
   reject a form submitted from another site. Keep it enabled.

2. RECEIVE AND CHECK THE FORM
   Backend/Pages/JianYi/Admin/Users/Edit.cshtml.cs

   using lines import names from other parts of C#/.NET.
   namespace groups related classes; it does not set the page URL.
   EditModel(... users) receives the AdminUserService registered in Program.cs.
   : PageModel gives the class Razor helpers such as Page() and ModelState.
   [Authorize(Roles = "Admin")] restricts both opening and submitting the page.
   [BindProperty] copies submitted fields into Input.
   SupportsGet = true also accepts a value from the URL when opening a page.
   Id is null when creating; an existing user's ID means editing.
   [TempData] keeps the success message for the next request after redirecting.

   OnGetAsync runs when the page opens. In Edit mode, it loads the user and
   fills Input. In Create mode, it shows an empty form.

   InputModel describes allowed fields. [Required], [StringLength],
   [EmailAddress] and [Compare] are server validation rules. A browser check
   can be bypassed, so the server checks again.

   OnPostAsync runs when Save/Create is clicked. Read it in this order:
   - Check the ID and mode-specific fields, such as the initial password.
   - Check ModelState.IsValid. Return Page() if input is invalid.
   - Build AdminUserInput from the allowed fields.
   - Get the acting administrator's ID from their signed-in account.
   - Call users.CreateAsync or users.UpdateAsync.
   - Set the success message and RedirectToPage back to the list.

   catch blocks turn expected failures into readable errors. InvalidPage()
   preserves ordinary entries but clears passwords. Redirect after success
   prevents a browser refresh from submitting the same operation again.

3. APPLY THE RULES
   Backend/JianYi/Administration/AdminUserService.cs

   CreateAsync trims and validates input, hashes the password, creates an
   account version (SecurityStamp), and calls the database store.
   UpdateAsync checks the submitted version and creates a new version.
   DeleteAsync checks the version before asking the store to delete.

   AdminUser.cs holds small data records and the expected error types.
   IAdminUserStore.cs lists the methods a user database store must provide.
   The interface is a contract; MySqlAdminUserStore is its actual SQL code.

4. SAVE TO MYSQL
   Backend/JianYi/Administration/MySqlAdminUserStore.cs

   OpenAsync opens a database connection. await using closes it afterwards.
   A transaction keeps related checks and a write in one operation.
   The store checks that the acting user is still an active Admin.
   INSERT creates; SELECT reads; UPDATE changes; DELETE removes a record.
   @name and @email are SQL parameters. AddWithValue supplies their values.
   Do not build SQL by joining text from a form into a query string.
   CommitAsync confirms the write. Failure before commit rolls it back.

   The Admin role is locked first during writes. This makes competing admin
   changes wait their turn. Self-protection and last-admin checks prevent
   accidental loss of administrator access.

   SecurityStamp checks stop an old form overwriting a newer edit. Changing
   it also invalidates old login sessions. Foreign keys block deletion of
   accounts with learning/discussion records; deactivate those accounts.

5. SHOW THE RESULT
   Backend/Pages/JianYi/Admin/Users/Index.cshtml.cs loads the user list.
   Frontend/Pages/JianYi/Admin/Users/Index.cshtml displays it using @foreach.
   Search/filter uses GET because it only reads data. Deletion uses POST,
   an explicit confirmation box and OnPostDeleteAsync.

   Follow the whole path:
   Form -> PageModel -> Service -> SQL store -> MySQL -> list page

C# WORDS YOU WILL SEE
  public/private       Who can access a member of a class.
  var                  Let C# infer a local variable's type.
  Task / async / await Wait for database work without blocking a server thread.
  CancellationToken    Stop work when the request is cancelled.
  string? / long?      This value can be missing (null).
  ??                   Use the value on the right if the left value is null.
  ! after a value      Tell the compiler it is not null; it is not a runtime check.
  =>                   Short syntax for an expression or a small function.
  record / with        Carry data; create a copy with selected fields changed.
  get / set / field    Read/write a property and its stored value.
  return               Finish this method and give its result to the caller.
  throw / catch        Report an error / handle an expected error.

TIMOTHY: BUILD YOUR FIRST FEATURE
1. Run the app and try the user example above.
2. Open your Admin quiz list pair:
   Frontend/Pages/Timothy/Admin/Quizzes/Index.cshtml
   Backend/Pages/Timothy/Admin/Quizzes/Index.cshtml.cs
3. Add the matching Edit.cshtml / Edit.cshtml.cs pair in those folders.
   Use Jian Yi's Create/Edit flow and your Figma design. Your fields are
   course, title, instructions and pass percentage. Save new quizzes as drafts.
4. Add quiz save/delete methods under Backend/Timothy/Quizzes, using the
   existing quiz reader and schema. A QuizService and SQL store can follow
   the same responsibilities as AdminUserService and MySqlAdminUserStore.
5. Complete Create -> list -> Edit -> Delete for an unused draft quiz first.
   Check duplicate course quizzes, invalid fields and non-Admin access.
6. Add question/option management next. Publish only when questions are valid
   and every question has exactly one correct option. Protect attempted quizzes
   from destructive changes. Then build taking, server marking and results.

Your seven layouts: overview (with previous attempts), take quiz, result,
Admin quiz list, quiz editor, question list, question editor.
Use the existing login and role checks. You do not need to copy password or
cookie code into the quiz module. Coordinate Program.cs, CSS and SQL changes
with Jian Yi. Comments should explain a step or rule, not every bracket.

CHECK BEFORE CALLING A FEATURE FINISHED
- A valid form saves, survives refresh and appears in MySQL.
- Invalid/duplicate input shows a useful error and does not save.
- Editing and deleting work for the intended record only.
- Old forms cannot overwrite a newer user edit.
- Users with related learning records cannot be deleted.
- Guests/Members cannot call Admin pages or POST actions.
- Disabling/changing a role ends the affected user's old login sessions.
- Your own Admin account cannot be deleted, disabled or demoted here.
- Logout, profile/password changes, menus and links still work.
- Try a narrow window and keyboard navigation as well as desktop clicks.

SQL deletion and deactivation are different operations. Demonstrate a real
DELETE of an unused record for the assignment's database criteria.
